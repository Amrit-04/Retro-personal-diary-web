BIOS POST vs win32.run

Same structure and pacing: lead-in, memory test, IDE channels, DMI verification. Brand names are reworded and the required lines from the brief are kept.

Splash

The reference direction is a branding splash with a loading bar. Ours uses the XP Home splash construction with our own wordmark and book mark in the brand position; no Windows flag, no “Windows XP” text.

Logon vs mitchivin.com

Navy page, inset two-tone field, hairline divider, account tile on the right, Restart in the footer. In the live build the tile is the Google account; this capture is the sample mode shown when no Firebase config is present.

Welcome

The blue welcome field between sign-in and the desktop. No reference capture was usable for this phase (the reference frames are black), so this is shown on its own.

Desktop vs Windows XP

Taskbar, tray, Start button and desktop icon treatment follow the reference. The wallpaper is our own generated Bliss-style image, not Microsoft's asset; the program list is the brief's.

Window frame vs Windows XP

The frame, title gradient, caption buttons and inner edge are the reference's values. The content here is our viewer (filename as the title, long date, photo, pre-wrapped text).

Start menu vs Windows XP

Header, orange rule, program column, entries column, footer and Log Off follow the reference geometry. Our items are the brief's three programs plus the seven most recent entries with thumbnails and short dates.

Message box

The Luna message box used for inline errors and for the “not installed yet” placeholder while the diary apps come later. No alerts.

Phone

No XP phone reference exists, so these follow the brief's mobile rules: 3–4 column icon grid, 44 px targets, full-screen sheets on 100dvh with safe areas, large close, Back closes the top window.

What to look at

  • The chrome is the reference's own CSS and markup, not an eyeballed approximation.
  • Our wordmark and open-book mark replace the Windows XP wordmark and flag in the same positions.
  • The Start button keeps the sampled glossy ladder from the reference; the taskbar is 30 px.
  • The Start menu covers the viewer's short third line in the Start-menu shot because the line ends behind the menu — that is occlusion, not clipping; with the menu closed the line is visible.
  • Nothing here is diary content: the entries are sample fixtures, and File Explorer / Minesweeper / New Entry open the placeholder dialog until you approve the look.

If the shell looks right, the next order of work is: locks and rules tests, auth, data, explorer, viewer, the editor and Minesweeper — then the performance pass. If something is off, name the screen and I will change it before anything else is built.
